# 智序 smart-blog 系统设计文档 v2

> 版本：v2.0（2026-11-12）
> 依据：docs/需求规格说明书-v2.md
> 编码规范：Java 遵循 knowin-workspace「Java 后端编码强制规范」（阿里黄山版基线+项目补充），要点见仓库根 AGENTS.md

## 1. 架构总览

```
┌──────────────────────────── 本地开发 / 未来服务器（形态一致）────────────────────────────┐
│                                                                                        │
│  浏览器 ──HTTP──▶ Nuxt3 SSR (Node :3000)  ──REST /api/v1 + JWT──▶  Spring Boot 3 (:8080) │
│                    │  SSR 直出 / SEO / Shiki / 暗色                  │                   │
│                    │                                                ├──▶ MySQL 8 :3306  │
│                    └── /api 代理（dev 用 Nuxt proxy，生产用反代）      │     （Flyway 迁移） │
│                                                                     └──▶ Redis :6379   │
│                                                                           缓存/限流/计数  │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

- **本地开发**：`docker/docker-compose.dev.yml` 只起 MySQL + Redis；后端 `mvn spring-boot:run`，前端 `pnpm dev`（Nuxt serverProxy 把 `/api/**` 转发到 :8080）
- **本地全栈联调**：`docker/docker-compose.yml` 起 mysql + redis + backend（分层 jar 镜像）+ frontend（Nuxt SSR 镜像）
- **服务器部署（暂缓，另起阶段）**：同一 compose + Caddy 反代；备案中用 `IP:8080` 暴露，备案后切 80/443 自动 HTTPS

## 2. 技术选型

| 层 | 选择 | 关键理由 |
|---|---|---|
| 后端框架 | Spring Boot 3.5.x / Java 21（LTS） | 2.7 已 EOL；jakarta 命名空间；虚拟线程可选讲点 |
| ORM | MyBatis-Plus（spring-boot3 starter）3.5.x | 保留 v1 资产（11 mapper），参数化查询延续 |
| 迁移 | Flyway | 基线 + 增量脚本，替代 `sql.init.mode=always` 和启动期 ALTER hack |
| 安全 | Spring Security 6 + BCrypt + JWT（jjwt 0.12） | 替换自写拦截器；无状态适配前后端分离 |
| 缓存/限流/计数 | Redis（Spring Data Redis + Lua 计数） | 浏览量缓冲落库、登录/留言限流、热点缓存 |
| API 文档 | springdoc-openapi + Knife4j 4.x | SB3 兼容的 OpenAPI3 |
| 数据库 | MySQL 8（utf8mb4） | 沿用，用户熟悉；连接池 HikariCP（默认） |
| 前端框架 | Nuxt 3.x + TypeScript + Vite | SSR/SSG 混合、SEO、约定式路由 |
| 样式 | Tailwind CSS + CSS 变量设计令牌 | 暗色优先、渐变光晕、组件化改造 v1 视觉资产 |
| 代码高亮 | Shiki（SSR 渲染时高亮，LRU 缓存） | 与 VS Code 同引擎；亮/暗双主题 |
| 交互 | @vueuse/motion（`prefers-reduced-motion` 遵循）+ cmdk 式自研 ⌘K | 轻量、可控 |
| 状态 | Pinia + useFetch/useAsyncData | Nuxt 生态标准 |
| AI | OpenAI 兼容 REST（配置 base-url/key/model） | 智谱/DeepSeek/通义等任选；异步+超时降级 |

## 4. 数据模型

### 4.1 ER 关系（改造后）

```
t_user 1──n t_article          t_category 1──n t_tag
t_article n──n t_tag      （新增关联表 t_article_tag）
t_article 1──n t_comment       t_message（自关联 parent_id 楼中楼）
t_link 1──1? t_link_apply      t_project（新表）
t_setting(KV) / t_diary / t_notice / t_login_log / t_operate_log(预留)
```

### 4.2 表变更清单（Flyway V2 起）

| 变更 | 内容 |
|---|---|
| 时间字段 | `t_article.create_time`、`t_comment`、`t_message`、`t_diary`、`t_notice`、`t_login_log` 等全部 CHAR(19) → `DATETIME`，脚本内 STR_TO_DATE 回填 |
| 标签关联 | 新表 `t_article_tag(article_id, tag_id)`；由 `t_article.tag_names` 逗号文本按名字回填；文章保存改走关联表，`tag_names` 保留只读冗余一版后废弃 |
| 索引 | `t_article(publish_status, is_top, create_time)`、`t_article(cid)`、`t_article_tag(tag_id)`、`t_comment(aid,status)`、`t_message(status,parent_id)`、`t_login_log(login_time)` |
| 密码 | `t_user.password` VARCHAR(32)→VARCHAR(72)，BCrypt 哈希；运行期首次登录自动升级 |
| AI | `t_article` 增加 `ai_summary VARCHAR(300)`、`ai_generated_at DATETIME` |
| 作品集 | 新表 `t_project(id, name, summary, description, tech_stack, cover, repo_url, demo_url, featured, sort, status, create_time, update_time)` |
| 友链申请 | 新表 `t_link_apply(id, site_name, site_url, site_desc, contact, status[0待审/1通过/2拒绝], remark, ip, create_time)` |
| 迁移策略 | V1 = 现有 schema.sql 全量基线（含 V1.1-batch1 列）；V2+ 每批一个文件，含回填与校验 SQL；`schema.sql` 与 `spring.sql.init` 退出历史舞台；`docs/sql/` 老脚本归档不再手工执行 |

### 4.3 审计与规范

- 全表统一 `id BIGINT AUTO_INCREMENT` 主键；新表带 `create_time DATETIME DEFAULT CURRENT_TIMESTAMP`
- 不引入外键约束（沿用 v1 约定，靠索引+服务层校验，注释说明取舍）

## 5. API 设计

### 5.1 契约

- 前缀 `/api/v1`；统一响应 `Result<T>{ code, message, data }`（code=0 成功；业务错误码见 `ResultCode` 枚举）
- 分页 `PageResult<T>{ list, total, page, size }`
- 认证：`Authorization: Bearer <accessToken>`；`POST /api/v1/auth/refresh` 轮换 refresh token（Redis 存白名单，可吊销）
- 错误：`BizException` → 全局处理器 → `Result`；参数校验 jakarta-validation → 400 + 字段错误
- 文档：Knife4j `/doc.html`（仅 dev/test profile 开放）

### 5.2 接口清单（按组）

| 组 | 端点（节选） | 权限 |
|---|---|---|
| auth | `POST /auth/login` `POST /auth/register` `POST /auth/refresh` `POST /auth/logout` `POST /auth/reset/request` `POST /auth/reset/confirm` `GET /auth/captcha` | 匿名（限流） |
| 内容-公开 | `GET /articles`（分页/搜索/筛选）`GET /articles/{id}` `GET /articles/hot` `GET /articles/{id}/neighbors` `GET /articles/{id}/related` `GET /categories` `GET /tags` `GET /notices` `GET /diaries` `GET /links` `GET /projects` | 匿名 |
| 互动 | `POST /articles/{id}/view` `POST /articles/{id}/like` `GET /articles/stats?slugs=` `GET/POST /comments` `GET/POST /messages` `DELETE /messages/{id}` `POST /link-applies` | 匿名（限流）/访客 |
| me | `GET/PUT /me/profile` `PUT /me/password` | 访客 |
| admin | `/admin/articles` CRUD+状态 `PUT /admin/articles/{id}/ai-summary`、`/admin/categories`、`/admin/tags`、`/admin/comments/{id}/audit`、`/admin/messages/{id}/audit|reply`、`/admin/link-applies/{id}/approve|reject`、`/admin/diaries`、`/admin/notices`、`/admin/links`、`/admin/projects` CRUD、`/admin/users`、`/admin/logs`、`/admin/settings`、`GET /admin/dashboard`、`PUT /admin/me/profile` | 管理员（role=0） |

> 旧 Thymeleaf 控制器（FrontController/AuthController/Admin*Controller）过渡期原样保留（继续走 Session），Nuxt 全功能对齐验收后整层删除，避免双写逻辑分叉。

## 6. 安全设计

| 风险 | 方案 |
|---|---|
| 弱口令存储 | BCrypt(cost=10)；Flyway 迁移 + 首次登录自动升级（校验 MD5 命中即重哈希落库） |
| 找回密码 | 邮箱验证码（`spring.mail` 可配置；验证码 Redis 5min 一次性）；未配置 SMTP → 管理员后台重置；删除「用户名+手机号」逻辑 |
| 暴力破解 | 登录失败计数（Redis `login:fail:{ip}` 5 次/15min 锁定）；验证码开关保留 |
| 限流 | Redis 滑动窗口：留言 1 条/30s/IP、友链申请 1 条/h/IP、点赞 60 次/min/IP；XFF 仅在 `trusted-proxies` 配置内取，默认取直连 IP |
| 越权 | 接口级：SecurityConfig 白名单（公开只读接口）+ 方法级 `@PreAuthorize("hasRole('ADMIN')")`；删除 admin 用户名硬编码。**注意：authorizeHttpRequests 规则先匹配先生效，`/api/v1/admin/**` 与 `/api/v1/me/**` 必须声明在宽泛的 `GET /api/v1/**` 放行之前**（集成测试 adminEndpointsEnforceRole 守护此边界） |
| JWT | access 2h / refresh 7d；HS256，密钥走 `JWT_SECRET` 环境变量；refresh 白名单可吊销（登出/改密即失效） |
| XSS | Markdown 渲染保留 v1 escapeHtml+sanitizeUrls；前端禁 `v-html` 于用户输入（Markdown HTML 由后端白名单净洗后输出） |
| 上传 | 保留白名单扩展名+UUID 重命名；增加魔数嗅探（jpeg/png/gif/webp）+ 5MB 上限；Nginx/反代禁 /uploads 执行权限 |
| 配置 | `application.yml` 无任何真实口令：DB/Redis/JWT/SMTP/LLM 全部 `${ENV:本地默认}`；`.env` 进 .gitignore，提供 `.env.example` |

## 7. 缓存与性能设计

| 机制 | 设计 |
|---|---|
| 浏览量 | `POST /view` → Redis `INCR view:{articleId}` + 浏览器会话去重 `viewed:{articleId}:{uuid}`（TTL 6h）；定时任务每 5min 批量 `GETDEL` 落库（单条 UPDATE，非逐条事务） |
| 站点设置 | Redis 缓存 `setting:all`，后台保存即 DEL（5s 内生效） |
| 热点文章 | `articles/hot` 缓存 10min |
| N+1 治理 | 分页 fill 改批量 `WHERE cid IN / uid IN` 一次查询；标签统计改 `SELECT tag_id, COUNT(*) GROUP BY`；评论列表改 JOIN 补标题 |
| 前端 | useAsyncData 复用 SSR 数据；文章页 payload 缓存（`routeRules: swr`，详情 60s、列表 30s） |

## 8. 前端设计（Nuxt3）

### 8.1 结构与路由

```
frontend/app/
├── pages/            # §3 页面清单一一对应（server routes: /api proxy、/sitemap.xml、/rss.xml、/og/[id].png）
├── components/       # ui/（按钮/卡片/输入等原子）+ biz/（ArticleCard/CommentTree/Toc/CommandPalette/AiSummaryCard...）
├── layouts/          # default（前台）/ admin（侧栏工作台）/ auth（居中卡片）
├── composables/      # useApi（统一 Result 解剖+401 刷新）、useTheme、useAuth
├── stores/           # auth（user/token）、settings
└── assets/css/       # tokens.css（设计令牌）
```

### 8.2 设计系统（现代科技风）

- 暗色优先：`@nuxtjs/color-mode`，`class` 策略防闪烁 + 内联脚本兜底
- 令牌：CSS 变量双层（`--bg/--surface/--text/--accent` × 亮暗两套）；亮色沿用 v1 纸感色板为基底微调，暗色为深空灰 + 品牌渐变（青→紫）光晕
- 字体：标题衬线（Noto Serif SC）+ 正文无衬线（系统栈）+ 代码 JetBrains Mono（本地子集化，不引 CDN）
- 动效：页面进入 fade-up、卡片 hover 抬升、打字机副标题；全部包 `@media (prefers-reduced-motion: no-preference)`
- 组件七态强制：每个业务组件补键盘（Tab/Enter/Esc）、焦点回返、空态、加载骨架、错误态、窄屏、明暗适配

### 8.3 SEO 与内容

- SSR 直出文章正文（后端返回渲染后 HTML + TOC 数据）；`useSeoMeta` 全覆盖；文章 JSON-LD（BlogPosting）+ 面包屑
- `/sitemap.xml`（server route 拉全量公开文章）、`/rss.xml`、`/og/[id].png`（satori 模板生成分享图，缓存）
- Shiki：服务端高亮，`dual` 亮暗双主题输出双 class，CSS 切换无闪烁；LRU 200 篇缓存
