# 智序 · 项目现状分析

对照《智序 · Smart ERP 个人博客系统开发需求文档》V1.0 与当前代码。本文件只做梳理，不改业务代码和数据库。

技术栈与文档一致：Java 8、Spring Boot 2.7.18、Thymeleaf、MyBatis-Plus 3.5.5、MySQL、Maven。表名是 `t_user`、`t_article` 等，不是文档里的 `sys_*` / `blog_*`。应继续用现有表，不要为了表名重建。

权限：`AuthInterceptor` 拦截 `/admin/**`（登录页除外）。未登录进后台登录页，非管理员同样拒绝。角色是 `t_user.role` 的 `0` / `1`，外加用户名 `admin`，没有独立角色表。密码是 MD5。登录有验证码和 `t_login_log`。

## 已实现

这些模块已有页面、接口和表，下一阶段应复用，不要重做。

| 模块 | 现状 |
|---|---|
| 前台导航与页脚 | 首页、博客、留言、日记、友链、关于；登录用户头像菜单；管理员才看到后台入口；退出是 POST |
| 首页 | 口号、最新文章、公告、最近日记，数据来自数据库 |
| 博客列表 / 详情 | 分页、标题正文搜索、栏目和标签筛选；详情渲染 Markdown；阅读量自增；公开文章才给前台看 |
| 评论 | 前台发表；可先审后发；后台通过、驳回、删除 |
| 留言板 | 列表、分页、发表、楼中回复；未通过不展示；后台审核、回复、删除 |
| 日记 | 前台时间线；后台新增、删除 |
| 友链 | 前台卡片（用站点地址取图标）；后台新增、编辑、删除、排序 |
| 关于 | 读站点设置里的 `about` |
| 后台壳 | 左侧菜单、顶栏、面包屑、统一样式 |
| 文章管理 | 查询、编辑、封面上传、公开/私密、热门、删除 |
| 栏目与标签 | 左栏目、右标签；新增和删除；删除有确认。标签在文章里是逗号文本，不是标签 ID |
| 公告 | 新增、删除、置顶；首页展示 |
| 用户 | 查询、锁定、改角色 |
| 登录日志 | 列表 |
| 站点设置 | 站名、副标题、页脚、关于、分页、阅读量、评论、留言、注册开关 |
| 个人中心 | 资料、头像、改密码（校验原密码） |
| 总览 | 文章、公开文章、评论、留言、友链、访问量，以及 Java / 系统信息 |

## 部分实现

有相近能力，但和文档字段或流程不完全一样。补这些要加字段或改交互，不要另起一套接口。

| 模块 | 已有 | 还缺 |
|---|---|---|
| 文章状态 | `isOpen`：公开 / 私密 | 草稿、已下线；SEO 标题、关键词、描述；置顶。热门可当作推荐的近似 |
| 文章详情 | 标题、摘要、封面、作者、时间、栏目、标签、阅读量、正文、评论、点赞 | 目录、上一篇下一篇、相关文章、分享、代码一键复制、图片预览 |
| 博客列表 | 关键词、栏目、标签、分页 | 发布时间范围、按阅读量排序的独立入口、评论数 |
| 首页 | 最新文章、公告、日记 | 个人介绍区、分类入口、热门标签、站点统计条、社交链接 |
| 栏目 | 名称、文章数、增删 | 描述、图标、排序、改名。现在只能新增，不能编辑 |
| 标签 | 名称、所属栏目、增删、按栏目查看 | 排序、改名。关联文章数若做，只能按标签文字精确匹配，不能当成外键统计 |
| 公告 | 标题、内容、置顶 | 没有单独的发布 / 下线状态，记录在就展示 |
| 日记 | 标题、内容、心情、时间 | 没有图片、没有发布状态、没有详情页 |
| 友链 | 名称、地址、描述、排序 | 没有 Logo 字段（前台临时读对方 favicon）、没有启用 / 停用 |
| 评论 | 审核和删除 | 没有管理员回复 |
| 总览 | 几项计数 | 没有 7 日 / 30 日图表、分类分布、待办、快捷入口。访问量是文章阅读次数合计，不是独立访问日志 |
| 用户 | 头像、昵称、账号、角色、状态、注册和最后登录 | 没有邮箱字段，没有删除用户 |
| 设置 | 基础文案和开关 | 没有 Logo、站点地址、SEO、备案、联系方式、上传类型和大小的配置页 |
| 密码 | MD5 | 文档要求的安全哈希还没换。更换会影响现有账号，需单独做 |

- 访问日志，以及据此画的趋势图
- 文章与标签的关联表 `blog_article_tag`（文档已说明这是以后的迁移，不是现在的前置条件）
- 独立角色表、通知中心、系统信息专页
- 顶栏通知入口

## 不要做的事

文档里的目标表名、`ADMIN` / `USER` 字符串角色、统一 JSON 响应，都和现有实现不同。现有页面是表单 POST 加重定向，不是一套 REST。

不要为了对齐文档而：

- 删表、改表名、清空数据
- 更换登录方式和现有 URL
- 引入新的权限框架或响应格式
- 用假数据填统计图
- 把栏目、标签改成“有编辑按钮但其实又插入一条”

## 改动量

日常使用的闭环已经在。把文档里的规划全部做完，工作量大约是再做一层新功能，不是把现在的博客重写一遍。

建议的下一阶段只补缺口，不重做已有页面：

1. 文章补草稿 / 下线，详情补上一篇、下一篇、相关文章。
2. 栏目、标签补编辑和排序；删除文案继续说明不会改文章里的标签文字。
3. 友链增加 Logo 和启用状态；友链申请单独做。
4. 总览只加真实待办（待审留言、待审评论），图表等有访问日志再做。
5. 操作日志、文件管理、导航配置放到更后面。

涉及文件会集中在已有的 `AdminArticleController`、`AdminContentController`、`FrontController`、`ArticleService`、`ContentService`，以及 `templates/admin`、`templates/front` 和 `schema.sql` 的增量字段。不要新建第二套 Controller。
